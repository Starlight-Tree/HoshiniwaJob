# 星庭ジョブの求人検索画面のUX調査

星庭ジョブの求人検索画面について、2026-10-27 に行った調査の記録。もとは別のリポジトリ（docunavi）の `docs/ux-research.md` に書いたもので、ここへ移した。内容は元の節のまま。プロジェクト名は「星庭ジョブ」に統一してある。以降の調査は、この文書に追記する。

## 2026-10-27 星庭ジョブの求人検索（A 案: 左にしぼり込み・右に一覧 / B 案: 上に大きな検索・カード）

対象: 星庭ジョブの画面。モックは非公開のキャンバス（Claude Design）。ダミーデータだけ。条件は 4 種類（地域 13・駅 11・職種 37〔5 区分〕・雇用形態 4）。求人は数百件規模を想定。

### 結論（私の見立て。未決）

- **A 案を土台にし、B 案の一部を取り入れる。** 理由: 条件の選択肢が多く（職種 37 件、地域 13 件）、求人が数百件規模で、絞り込みが主な操作。左の列は、選択肢と件数が最初から見える（Baymard。ただし通販の調査）。
- 取り入れる B 案の部分: 結果の件数を大きく見せる／選んだ条件をチップで結果の上に並べ、1 つずつ外せるようにする。
- A 案の欠点: 職種 37 件が縦に長い（区分ごとに折りたたむ）／選んだ条件が結果の上に出ない／件数付きの条件には、条件ごとの件数を返す API が要る。
- B 案の欠点: 職種の全 37 件を、チップで並べると溢れる／条件を選んだあと、一覧が画面の下に押される／条件ごとの件数が見えない。
- 両案に共通して足りない動作: 0 件のときの案内（条件を緩める提案）／選んだ条件の表示と解除／並べ替え。

### 採用と実装の状況（2026-10-27）

- ユーザーの選択: 「OK 進んで」（A 案を土台に、B 案の件数・チップを足す案への同意）。
- 実装した: 左に条件（件数付き）、右に一覧／結果の件数を大きく表示／選んだ条件のチップ（1 つずつ外せる、全クリア）／職種を区分ごとに折りたたみ／0 件の案内／条件ごとの件数を返す API（`/api/facets`）。
- 実機の確認（Playwright、1280px）: 一覧、条件を選んだ後（チップと件数の更新）、0 件、詳細、ページ送り。390px は横スクロールが出ないことだけ確認。
- 並べ替えは、まだ無い。給与の単位は、モックの「万」の表記に合わせて、表示だけ変えた。
- 未確認: 数百件規模のデータでの表示の長さ、本物のブラウザー（Safari など）、キーボードだけでの操作。
