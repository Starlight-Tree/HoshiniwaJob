# docs/ を触るとき

どの文書が何の正本かは [docs/CLAUDE.md](../../docs/CLAUDE.md)。

- 確認していないことを「確認済み」と書かない。状態は台帳冒頭の凡例（報告 / ソースで確認 / 未確認）に従い、意味を言い換えない（[台帳](../../docs/image-gen-resources.md)）。推測は推測と書き、事実の文にしない
- 数字と状態には、日付と測り方を添える
- 同じ事実を複数の文書に書かない。画像生成（Vertex AI のジョブ）の事実は台帳に書き、他からはリンクで指す。台帳の 1 節（区別すること）・2 節（デプロイ済みの設定）・3 節（実行の記録）・4 節（ソースとデプロイの関係）の区別を混ぜない。成功版はイメージのダイジェストで書く
- 画像生成のデプロイ・モデル・保存先を変えたら、台帳の「6. 変更したときの完了条件」を満たすまで「完了」と書かない。デプロイ・実行・生成・保存と回収・画面表示は、別々に書く
- 文書やファイルを移す・改名するときは、リンク・バッククォートのパス・節名・コードのコメントの参照を `git grep` で洗い、全部直す
- 秘密（キー・トークン・接続文字列）、資料の本文、機密を含むプロンプトは書かない。プロジェクト ID・リソース名は秘密ではないので、台帳の方針（台帳冒頭）どおりに書く。登録語（`.git/sensitive-terms`）に当たるものは書かない。確認は `scripts/check-sensitive-terms.sh`
- 出力を証跡として置く前に、目で確かめる（`docs/image-gen-evidence/README.md`）
- 直したあと、別の目（`docs-reviewer`）で確かめてよい。指摘は、再現できたものだけを取る
