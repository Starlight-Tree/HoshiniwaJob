# 並行作業・サブエージェント

- 読み取りの調査・草案・レビュー・読み取りの検査は、サブエージェントに任せてよい（`.claude/agents/` の `repo-researcher` `docs-reviewer`、Workflow の読み取り専用の確認役）。
- **承認が要る操作は、すべて任せない。** メインの会話だけが、承認を得て行う。正は、ルートの `CLAUDE.md` の「承認を得てから」の各項目、`.claude/settings.json` の `ask`、`.claude/hooks/guard-*.py`。主なもの: コミット・プッシュ・デプロイ、`git reset` / `git restore`、`CLAUDE.md` と `.claude/` の変更（規則・フック・権限・スキル）、ファイルやデータの削除と、元に戻す操作、実 API（Gemini など）、R2 への書き込み、`seed` / `seed-images`、マイグレーションの適用、本番の DB の操作、gcloud・gh・wrangler・infisical・prisma・MCP の書き込み系、新しいサービス・言語・DB の追加、保留中の項目（Python の版・モデル名など）と画像生成のモデル・保存先の変更。
- 設計の判断と、失敗の原因の判断は、丸投げしない。
- 子の出力は、取り込む前にメインが確かめる。**再現できない指摘は、事実として扱わない。** 「確認した」は、何を読み・実行して確かめたかが書かれているものだけを取る。
- 子に書き込ませるなら、触ってよいファイルを明示し、同じファイルを並行して触らせない（分けられなければ worktree）。台帳（`docs/image-gen-resources.md`）は、並行して触らせない。`scripts/verify.sh` のように書く検査（テスト用 DB・`.next`）も、並行して流さない。
- 子にも、`.env` と `backups/` と登録語（`.git/sensitive-terms`）を読まないこと、値を出さないことを伝える。
- `.claude/agents/` の定義の `tools` は、公式文書では許可リストとして働くとされる（この環境での実機の確認は未実施）。Workflow の子に及ぶかは文書に無く、未確認。バックグラウンド起動の子は、`tools` に書いても多くの組み込みツールが外される。どれも当てにせず、指示でも「書かない」と伝える。
